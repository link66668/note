# 仓库目录结构指南要求

> 本要求用于统一 Obsidian 仓库的文件归属、时期归档、科目目录、原始资料和要求类文件位置。根目录中的科目文件夹表示当前时期正在使用的科目；已结束时期的全部科目归档到“大一上”“大二下”等时期文件夹。每个科目的原始资料统一存放在该科目的 `原件` 文件夹中，所有要求类 Markdown 文件统一存放在仓库根目录下的 `要求` 文件夹中。

## 主要内容

- 仓库根目录的用途
- 当前时期与历史时期的区分
- 科目文件夹划分规则
- `原件` 文件夹的定义与使用
- 要求类文件的统一位置
- 文件创建、移动和重命名规则
- 目录结构检查清单

---

## 一、基本原则

### 1. 按科目划分

- 课程笔记、原始资料、真题、复习资料和科目级汇总文件必须放入对应的科目文件夹。
- 不同科目的文件不得混放在同一课程目录中。
- 课程内容不得长期散放在仓库根目录。
- 文件涉及多个科目时，放入主要归属科目，并通过 `related` 或正文 wikilink 连接其他相关科目，不为方便而复制多个内容相同的文件。

### 2. 按时期区分当前与归档

- 科目文件夹直接位于仓库根目录时，表示该科目属于**当前时期**并处于使用或整理状态。
- “大一上”“大一下”“大二上”“大二下”等大时期文件夹用于归档相应时期已经结束的全部科目文件夹。
- 时期结束后，应将该时期的科目文件夹整体移入对应时期文件夹；科目内部的 `原件`、`笔记`、`真题整理` 和汇总文件结构保持不变。
- 同一份科目资料不得无说明地同时保留在根目录和历史时期文件夹；跨时期继续使用的科目可暂留根目录，归档时再整体移动。
- `要求`、`.obsidian`、`AGENTS.md`、`CLAUDE.md` 和 `README.md` 属于仓库级内容，不随时期归档。

### 3. 根目录保持简洁

仓库根目录只保留以下全局内容：

- 当前时期的科目文件夹。
- “大一上”“大二下”等历史时期归档文件夹。
- `要求` 文件夹。
- `.obsidian`、`.git`、`.claudian` 等仓库配置目录。
- `AGENTS.md`、`CLAUDE.md`、`README.md` 等仓库级入口或配置文件。
- 其他确有全仓库作用、且不能归入某一科目的文件。

临时脚本、检查结果和中间文件使用完毕后应及时清理，不得长期占用根目录。

## 二、标准目录结构

### 1. 仓库级结构

```text
.
├─ 要求/
│  ├─ 仓库目录结构指南要求.md
│  ├─ 通用要求.md
│  ├─ 复习计划安排要求.md
│  ├─ 总复习编写要求.md
│  ├─ 真题合订编写要求.md
│  └─ 优化ocr要求.md
├─ 科目一/
│  ├─ 原件/
│  └─ 其他科目内容
├─ 科目二/
│  ├─ 原件/
│  └─ 其他科目内容
├─ 大二下/
│  ├─ 已归档科目一/
│  │  ├─ 原件/
│  │  └─ 其他科目内容
│  └─ 已归档科目二/
│     ├─ 原件/
│     └─ 其他科目内容
├─ .obsidian/
├─ AGENTS.md
├─ CLAUDE.md
└─ README.md
```

- 根目录中的“科目一”“科目二”表示当前时期科目。
- `大二下/` 仅作时期归档示例；实际名称按用户建立的时期文件夹为准。
- 历史时期文件夹中直接放置该时期的各科目文件夹，不在其中复制 `要求` 或仓库级配置。

### 2. 科目级结构

每个科目文件夹至少应包含 `原件` 文件夹。其他子目录根据该科目的实际内容建立：

```text
科目名称/
├─ 原件/
├─ 笔记/          # 可选：正式章节笔记与课程索引
├─ 真题整理/      # 可选：已经转写或整理的试卷资料
└─ 科目级汇总文件  # 可选：总复习、真题合订、提炼笔记等
```

- 不为了形式统一强制建立没有实际用途的空目录，`原件` 除外。
- 已有合理目录可以保留；新增目录名称应简洁、明确，并在同一科目中保持一致。

## 三、`原件` 文件夹规则

### 1. 文件夹含义

每个科目目录中名为 `原件` 的文件夹，是该科目**未经知识整理的原始资料统一存放位置**。

适合放入 `原件` 的内容包括：

- PDF、PPT、PPTX、DOC、DOCX 等原始课件或教材。
- 扫描件、试卷原图、原始截图和下载的网页资料。
- 教师提供的原始附件、数据文件和代码压缩包。
- PaddleOCR、MinerU 等工具直接生成、尚未人工整理的原始转写文件。
- 其他用于核对正式笔记的来源文件。

### 2. 原件保护

- 原件原则上保留原始文件名和原始内容。
- 不直接覆盖、润色或重排 `原件` 中的来源文件。
- 需要整理时，在科目目录的适当位置创建新的 Markdown 文件，并在 frontmatter `source` 中记录 `原件` 的相对路径。
- 同一原件存在多个版本时，应在文件名中保留可辨识的版本、日期或版次，不得互相覆盖。
- 删除或替换原件前必须确认其整理结果、引用关系和备份情况。

### 3. 旧目录迁移

- 已有的“课件”“课程资料”或其他原始资料目录，不得在未检查引用关系时直接批量移动。
- 迁移到 `原件` 前，应检查 frontmatter `source`、普通 Markdown 链接、脚本路径和课程索引。
- 完成迁移后，应更新所有受影响的相对路径，并验证链接目标存在。

## 四、要求类文件规则

### 1. 统一位置

所有要求类 Markdown 文件统一放入仓库根目录下的 `要求` 文件夹，包括：

- 仓库通用要求。
- 复习计划、总复习、真题合订等专项要求。
- OCR 优化要求。
- 仓库目录结构、命名或其他长期维护要求。

新建要求类文件时，默认使用简洁且明确的 `主题要求.md` 命名方式，不得散放在仓库根目录或科目目录。

### 2. 根目录例外

- `AGENTS.md` 与 `CLAUDE.md` 是仓库级规则入口文件，继续保留在根目录。
- 修改其中任一文件时，必须同步修改另一个文件，并保持内容完全一致。
- `README.md` 是仓库导航文件，继续保留在根目录。

### 3. 引用要求

- Obsidian 正文中的内部引用使用 wikilink，例如 `[[通用要求]]`。
- `AGENTS.md`、`CLAUDE.md`、脚本和配置文件需要读取要求文件时，使用从仓库根目录开始的相对路径，例如 `要求/通用要求.md`。
- 移动要求文件后，应检查纯文本路径引用、编辑器工作区状态和插件记录，避免残留旧路径。

## 五、文件放置流程

### 1. 新建文件

新建文件前依次判断：

1. 是否为要求类文件；是则放入 `要求`。
2. 是否属于当前时期科目；是则放入根目录下对应科目目录。
3. 是否属于已经结束的时期；是则放入对应时期文件夹中的科目目录。
4. 是否为未经整理的来源资料；是则放入对应科目的 `原件`。
5. 是否为正式课程笔记；是则放入该科目现有的 `笔记` 或对应知识目录。
6. 是否为仓库级入口或配置文件；只有确有全局用途时才留在根目录。

### 2. 移动或重命名

- 移动前确认目标目录存在，且目标位置没有同名文件。
- 不覆盖内容不同的同名文件。
- 移动后检查 wikilink、Markdown 链接、frontmatter `source`、`related`、课程索引和脚本路径。
- 大批量移动科目资料前，先建立来源路径与目标路径映射，不得边猜测边迁移。
- 将科目归档到时期文件夹时，必须整体移动科目目录，不拆散 `原件`、笔记和汇总文件。
- 目录迁移完成后，应在 Obsidian 中验证文件可打开、链接可跳转、来源路径可定位。

## 六、发布前检查清单

- [ ] 所有课程内容都位于对应科目文件夹中
- [ ] 根目录中的科目均属于当前时期，历史科目已归档到对应时期文件夹
- [ ] 历史时期文件夹内直接按科目归档，没有混入 `要求` 或仓库级配置
- [ ] 每个科目目录都存在 `原件` 文件夹
- [ ] 原始 PDF、课件、扫描件及未经整理的 OCR 文件放在对应科目的 `原件` 中
- [ ] 正式笔记没有误放入 `原件`
- [ ] 所有要求类 Markdown 文件均位于 `要求` 文件夹
- [ ] `AGENTS.md`、`CLAUDE.md` 和 `README.md` 保留在仓库根目录
- [ ] `AGENTS.md` 与 `CLAUDE.md` 内容完全一致
- [ ] 仓库根目录没有散落的课程文件、已结束时期的未归档科目或临时处理文件
- [ ] 移动文件后已更新纯文本路径和 frontmatter `source`
- [ ] wikilink、课程索引、脚本路径和 Obsidian 工作区引用均可正常使用
- [ ] 未覆盖、删除或遗漏任何来源文件

## 本章小结

| 项目 | 核心要求 |
|---|---|
| 课程划分 | 课程文件按科目文件夹归类 |
| 时期划分 | 根目录科目表示当前时期；已结束科目按“大二下”等时期文件夹归档 |
| 原始资料 | 每个科目的 `原件` 文件夹是统一原件存放位置 |
| 正式笔记 | 放在科目目录的 `笔记` 或其他明确知识目录中 |
| 要求文件 | 统一放入仓库根目录下的 `要求` 文件夹 |
| 根目录 | 保留全局配置、入口文件、当前时期科目和历史时期归档目录 |
| 移动维护 | 移动后检查来源路径、链接、索引和工作区状态 |

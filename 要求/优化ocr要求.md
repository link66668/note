# 优化 OCR 要求

> 本笔记用于规范 PaddleOCR、MinerU 等工具从书籍 PDF 转写得到的 Markdown 文件，重点修复 OCR 对 `#` 标题层级的误判，并依据原书目录重建文档结构。优化时必须保留原文全部有效内容，不得因调整标题、目录或排版而删减正文、题目、公式、解答、表格及图示信息。

## 主要内容

- 优化范围与基本原则
- 原书目录的提取与核对
- 标题层级的重建规则
- OCR 伪标题的识别与处理
- 推荐文件结构与编辑流程
- 内容、公式、图片与题解的保留要求
- 输出文件命名与发布前检查

---

## 一、适用范围与优先级

### 1. 适用文件

本规范适用于以下文件：

1. PaddleOCR、PaddleOCR-VL 等工具生成的 Markdown 文件。
2. MinerU、Nougat 或其他 PDF 解析工具生成的 Markdown 文件。
3. 由扫描版教材、习题集、竞赛教程、论文集等资料转写得到的 Markdown 文件。
4. 已有正文基本完整，但标题层级、章节顺序或目录结构混乱的 Markdown 文件。

### 2. 规则优先级

执行优化时，结构判断按以下优先级进行：

1. **原书目录**：是章节名称、编号、顺序、层级与从属关系的最高标准。
2. **原 PDF 正文**：用于核对目录项对应的章节起始位置、正文范围和跨页关系，不得在无可靠依据时推翻原书目录。
3. **用户最新的明确要求**：用于确定输出形式、整理范围和其他个性化要求。
4. **[[通用要求]]及本规范中的格式规则**。
5. OCR 工具自动生成的 `#`、`##`、`###` 等标题标记。

> [!important] 原书目录是结构整理的最高标准
> OCR 生成的标题标记只作为待核验线索，不能直接视为正确结构，也不得用于推翻原书目录。章节名称、编号、顺序、层级和从属关系必须以原书目录为最高标准；原 PDF 正文、页眉、章节起始页和上下文只用于定位与复核。目录缺页、残损或无法可靠辨识时，才可根据原 PDF 正文暂定结构，并必须使用 Warning Callout 标明待核验部分。

### 3. 默认处理方式

- 默认新建结构优化后的文件，不直接覆盖 OCR 原文件。
- 默认保留为一个完整文件，不主动拆分章节；只有用户明确要求时才拆分。
- 默认只调整结构、排版和明确的 OCR 格式错误，不擅自改写知识内容。
- 若目录或正文无法可靠辨识，应保留原文并标注疑点，不得猜测章节名称或补造内容。

## 二、优化前必须完成的检查

### 1. 完整阅读规范与来源

开始编辑前必须：

1. 完整阅读[[通用要求]]。
2. 读取待优化的 OCR Markdown 文件。
3. 查找并读取原书目录；目录可能位于 Markdown 前部、原 PDF 的目录页或单独的目录文件中。
4. 原 PDF 可用时，对照目录页、章节首页、页码及正文顺序进行复核。
5. 记录源文件的章节数、目录项数、图片数、表格数、公式块数和现有标题数，作为优化后的完整性核对基线。

### 2. 建立目录映射表

正式修改正文前，应先整理原书目录映射。推荐格式如下：

| 原书层级 | 原书编号 | 原书标题 | 起始页 | 优化后格式 |
|---|---|---|---|---|
| 章 | 第1章 | 章节名称 | 1 | `## 第1章 章节名称` |
| 节 | 1.1 | 节名称 | 1 | `### 1.1 节名称` |
| 章内栏目 | 无或题型一 | 栏目名称 | 5 | 加粗段落标签 |

目录映射表用于确认以下内容：

- 章、节的数量是否完整。
- 编号与名称是否和原书一致。
- 正文出现顺序是否与目录一致。
- OCR 是否漏掉、重复或误识别目录项。
- 哪些 `#` 是真正标题，哪些只是 OCR 伪标题。

### 3. 目录缺失时的处理

如果 OCR 文件中没有完整目录：

1. 优先从原 PDF 的目录页提取。
2. 再根据章节首页、页眉、页码及连续编号交叉核对。
3. 无法确认的标题只保留为普通文本或加粗标签。
4. 在相应位置加入 Warning Callout，说明目录缺失或层级尚未核验。

> [!warning] 禁止凭空重建目录
> 没有可靠来源时，不得仅根据字体大小、OCR 自动标题或个人理解推断完整目录。

## 三、标题层级重建规则

### 1. 标题层级上限

最终文件只使用 H1、H2、H3、H4：

| Markdown 层级 | 用途 | 示例 |
|---|---|---|
| H1 | 整份笔记的唯一标题 | `# 全国大学生数学竞赛解析教程` |
| H2 | 前言、目录、章、附录等主要模块 | `## 第1章 极限、函数与连续` |
| H3 | 原书各章下的正式节 | `### 1.1 竞赛要点与难点` |
| H4 | 原书节下具有目录依据的正式小节 | `#### 1.1.1 函数极限` |
| 加粗标签 | 不属于原书目录层级的题型、方法、步骤、定理、例题组等内容 | `**题型一：函数极限**` |

- 一个文件只能有一个 H1。
- 允许使用 H4，但必须有原书目录、章节首页或正文结构等可靠依据，不得仅按 OCR 样式推断。
- 不使用 H5、H6 或更深标题；原书层级超过 H4 时，用加粗标签、列表等非标题结构承载，并保留原编号与从属关系。
- 不允许标题跳级。
- 书名页、出版社、作者、编委会等信息不得各自误设为 H1。

### 2. 有“章—节”目录的书籍

当原书目录包含“章—节”两级时，统一映射为：

```markdown
# 书名

## 第1章 章标题

### 1.1 节标题

**题型一：题型名称**

**1. 方法名称**
```

其中：

- “第1章”使用 H2。
- “1.1”使用 H3。
- 节内的“题型一”“方法1”“情形一”等使用加粗段落标签，不继续增加标题层级。

### 3. 有三级目录的书籍

当原书目录在“章—节”下还列有正式小节时，第三级目录项使用 H4：

```markdown
## 第1章 章标题

### 1.1 节标题

#### 1.1.1 小节标题
```

只有原书目录、章节首页或正文结构能够可靠证明其为正式小节时，才可使用 H4；普通题型、方法、步骤、例题和图题不得因此升级为 H4。

### 4. 没有章编号的书籍

若原书只有若干并列主题，没有“第几章”编号：

- 原书一级目录项使用 H2。
- 原书二级目录项使用 H3。
- 原书三级目录项使用 H4。
- 第四级及更深内容使用加粗段落标签、有序列表或 Callout。

### 5. 前置与附加内容

以下内容通常作为 H2 主要模块处理：

- 内容简介
- 前言
- 第一版前言、第二版前言
- 目录
- 附录
- 参考文献
- 索引
- 本书小结

书名页中的系列名、作者、出版社、出版地、版次、ISBN 等应整理到“书目信息”模块中，不得把每一项设置成独立标题。

### 6. 标题文字要求

- 尽量保留原目录中的编号和标题原文。
- 只修复明确的空格、全半角、错别字或 OCR 粘连问题。
- 对无法确认的文字使用 Warning Callout 说明，不静默改写。
- 同级标题保持统一格式，例如不要混用“第1章”“第一章”和“Chapter 1”。
- 标题中不放完整题干、长公式、解答过程或页码点线。

## 四、OCR 伪标题的识别与处理

### 1. 常见伪标题

OCR 经常把以下内容错误识别为标题：

| 误识别内容    | 错误示例              | 正确处理                      |
| -------- | ----------------- | ------------------------- |
| 书名页信息    | `# 科学出版社出版`       | 普通文本或书目信息字段               |
| 题型标签     | `# 题型一、函数极限`      | `**题型一：函数极限**`            |
| 方法名称     | `## 1. 利用基本极限`    | `**1. 利用基本极限**`           |
| 题目或例题    | `### 例1.1 求极限`    | 普通例题段落                    |
| 解答起始语    | `##### 解 先求偏导数`   | `**解**：先求偏导数……`           |
| 注释       | `##### 【注】……`     | `**注**：……` 或 Note Callout |
| 定理正文     | `##### 定理4.1 设……` | 加粗定理名并保留完整正文              |
| 公式或编号    | `# 4. 曲线的渐近线`     | 结合目录判断；非目录项时改为加粗标签        |
| 图题、页眉、页码 | `## 图3.2`         | 图示文字说明或普通图题               |

### 2. 判断一个标题是否真实

只有同时满足以下条件时，才应优先认定为正式标题：

1. 能在原书目录中找到对应项，或能在章节首页可靠确认。
2. 编号与前后章节连续。
3. 标题内容能概括随后一段正文，而不是题干、解答或公式的一部分。
4. 层级与相邻目录项一致。
5. 标题位置与原书页码、章节起始位置基本对应。

若只满足其中一两项，不应直接保留 OCR 给出的 `#`。

### 3. 错误标题的降级方式

根据内容性质选择处理方式：

1. 题型、方法或步骤名称：改为加粗段落标签。
2. 定义、定理、核心结论：使用块引用，并加粗名称。
3. 注释、提醒、OCR 疑点：使用 Obsidian Callout。
4. 例题名称：使用 `**例 1.1**：`，不设为标题。
5. 解答起始：使用 `**解**：`，并保持解答紧随题目。
6. 图题或表题：改为普通说明文字。
7. 页眉、页脚、重复书名和孤立页码：确认不承载知识信息后删除。

## 五、推荐的文件整体结构

### 1. 标准模板

```markdown
---
title: 书名
course: 课程或主题
tags:
  - 主题
  - OCR整理
created: YYYY-MM-DD
source:
  - "原始文件相对路径"
---

# 书名

> 用两至三句话说明资料来源、覆盖范围与结构优化目的。

## 主要内容

- 第1章 章标题
- 第2章 章标题

---

## 书目信息

保留作者、出版社、版次、ISBN 等必要信息。

---

## 前言

完整保留前言正文。

---

## 目录

完整保留原书目录及原页码。

---

## 第1章 章标题

### 1.1 节标题

正文。

**题型一：题型名称**

正文。

**例 1.1**：题目。

> [!answer]- 答案
> 解答与解析。

---

## 本书小结

总结覆盖范围；新增总结必须明确标注为 AI 补充。
```

### 2. 原目录的保留方式

- 原书目录不得被新的“主要内容”列表替代。
- “主要内容”用于概览，“目录”用于忠实记录原书章节与页码。
- 可修复目录中的 OCR 错行、断行和点线混乱，但不得删除页码或合并不同目录项。
- 如需增加 Obsidian 跳转链接，应保留原目录文字，并确保链接目标真实存在。

### 3. 大型书籍的处理

- 单文件过大时仍先完成完整目录映射，再决定是否拆分。
- 未经用户明确要求，不主动把一本书拆成多个文件。
- 用户要求拆分时，按章建立文件，并创建一份总目录笔记。
- 拆分后的章节文件应通过 `related` 和正文 wikilink 相互连接。

## 六、正文与知识信息保留要求

### 1. 零丢失原则

结构优化不得删除或概括替代以下内容：

- 定义、定理、性质、结论及成立条件。
- 公式、符号、变量限制和完整推导。
- 例题、练习题、真题、答案和解析。
- 表格、代码、注释和引用。
- 图片中承载的图形关系、坐标、数值、趋势和结论。
- OCR 无法可靠辨识但仍可能有意义的原文片段。

允许删除的内容仅限于经确认不承载知识信息的重复页眉、孤立页码、装饰性元素，以及按[[通用要求]]必须删除或脱敏的无关隐私信息。

### 2. 正文顺序

- 原则上按照原书页序和目录顺序排列。
- OCR 将跨页段落打断时，可以合并被错误分割的同一自然段。
- OCR 将题干与解答错位时，可以恢复原书顺序，但必须核对题号与上下文。
- 不得为了“更好理解”任意移动公式、题目或证明，导致引用关系改变。

### 3. OCR 不确定内容

对于乱码、公式残缺、图中标记模糊或原文矛盾，使用以下格式：

```markdown
> [!warning] OCR 内容待核验
> 此处原文或公式无法可靠辨识，已保留当前 OCR 结果，需对照原 PDF 复核。
```

不得通过删除、猜测或自行补全来隐藏不确定性。

## 七、公式、表格、图片与题解

### 1. 数学公式

- 行内公式使用 `$...$`，独立公式使用 `$$...$$`。
- 只修复明确的 LaTeX 定界符、命令、括号和上下标错误。
- 不得仅凭常识改变原公式的数学含义。
- 标题中误混入的公式应移回正文，并保持与前后文字的逻辑关系。

### 2. 表格

- 表格统一使用 Obsidian 原生 Markdown 管道表格。
- OCR 把表格拆成散乱文本时，应按原表的行列关系重建。
- 无法确认合并单元格或列关系时，应说明疑点，不得猜测。

### 3. 图片

- 最终 Markdown 文件不得保留图片嵌入、HTML 图片标签或 MinerU 图片路径。
- 必须逐图查看并转写图片承载的信息。
- 函数图像、几何图、统计图等应转为完整文字描述；能够可靠重构的结构图可使用 Mermaid。
- 公式图、表格图和代码图分别转为 LaTeX、Markdown 表格和代码块。
- 装饰图应注明其不增加新的知识信息，然后移除图片本身。

### 4. 题目与答案

- 题干必须完整保留在正文中。
- 答案、解答和解析使用 `> [!answer]-` 折叠 Callout。
- 答案 Callout 内的每一行都必须带 `>`。
- 手写答案或 OCR 识别答案必须标明来源与待核验状态，不得默认视为标准答案。

## 八、推荐编辑流程

### 1. 第一阶段：建立基线

1. 复制源文件，确定新文件名。
2. 统计原文件行数、字符数、标题数、图片数、表格数和公式块数。
3. 提取原书目录并建立目录映射表。
4. 标记章节起点、节起点和疑似伪标题。

### 2. 第二阶段：重建结构

1. 添加合规 YAML frontmatter。
2. 设置唯一 H1。
3. 将章级目录项统一设为 H2。
4. 将节级目录项统一设为 H3。
5. 将有可靠结构依据的正式小节设为 H4。
6. 将 H4 以下层级以及不属于目录的题型、方法、步骤等深层结构改为加粗标签、列表或其他非标题结构。
7. 将解答、注释、定理、图题等伪标题恢复为对应正文格式。
8. 按原书目录检查章节顺序和编号连续性。

### 3. 第三阶段：清理格式

1. 修复明确的段落断行和多余空行。
2. 修复明确的 LaTeX 与 Markdown 语法错误。
3. 重建表格并转写图片信息。
4. 将答案与解析放入折叠 Callout。
5. 删除残留 HTML 图片标签、图片路径和无知识信息的装饰元素。

### 4. 第四阶段：逐项核对

1. 逐章核对目录项与正文标题。
2. 按页或内容块核对题目、公式、答案、表格和图片。
3. 比较优化前后的内容量，调查异常减少的原因。
4. 在 Obsidian 阅读模式中检查 YAML、标题、公式、表格、Callout 和 wikilink。

## 九、输出文件要求

### 1. 文件命名

默认命名方式：

```text
原文件名-结构优化.md
```

例如：

```text
全国大学生数学竞赛解析教程（上册）-结构优化.md
```

- 不覆盖原 OCR 文件。
- 文件名应简洁，必要时去掉下载站点、随机编号和冗余转换器后缀。
- 如果用户指定文件名，以用户指定名称为准。

### 2. 来源记录

YAML 中的 `source` 应记录原始 PDF 和 OCR Markdown 的相对路径。正文引言应说明该文件是结构优化版本，并明确原文件仍被保留。

### 3. 新增内容标记

凡原书没有、由 AI 增加的说明、总结或辅助解释，都必须明确标注“AI 补充”，不得与原文混写。

## 十、发布前检查清单

- [ ] 已完整阅读[[通用要求]]
- [ ] 已找到并核对原书目录或章节首页
- [ ] 已建立原书目录与 Markdown 标题映射
- [ ] 全文只有一个 H1，且与 frontmatter `title` 一致
- [ ] 章级目录项均为 H2
- [ ] 节级目录项均为 H3
- [ ] 原书正式小节确需继续细分时使用 H4，且有可靠结构依据
- [ ] 全文不存在 H5、H6、更深标题或标题跳级
- [ ] 题型、方法、解答、注释、公式和图题未被误设为正式标题
- [ ] 标题编号、名称和顺序与原书目录一致
- [ ] 原书目录及页码已完整保留
- [ ] 章节数和节数与目录一致，无漏章、漏节或重复章节

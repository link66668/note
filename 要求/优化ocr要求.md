# 优化 OCR 要求

> 本笔记用于规范 PaddleOCR、MinerU 等工具从书籍、课件等资料转写得到的 Markdown 文件，重点修复 OCR 对 `#` 标题层级的误判，并依据可靠目录或原始结构重建文档。优化时必须保留原文全部有效内容，不得因调整标题、目录或排版而删减正文、题目、公式、解答、表格及图示信息。

## 主要内容

- 优化范围与基本原则
- 原书目录的提取与核对
- 标题层级的重建规则
- OCR 伪标题的识别与处理
- 推荐文件结构与编辑流程
- 内容、公式、图片与题解的保留要求
- 书籍类与课件类图片的分类处理
- 输出文件命名与发布前检查

---

## 一、适用范围与优先级

### 1. 适用文件

本规范适用于以下文件：

1. PaddleOCR、PaddleOCR-VL 等工具生成的 Markdown 文件。
2. MinerU、Nougat 或其他 PDF 解析工具生成的 Markdown 文件。
3. 由扫描版教材、习题集、竞赛教程、论文集等资料转写得到的 Markdown 文件。
4. 已有正文基本完整，但标题层级、章节顺序或目录结构混乱的 Markdown 文件。

### 2. 规则优先级

执行优化时，结构判断按以下优先级进行：

1. **原书目录**：是章节名称、编号、顺序、层级与从属关系的最高标准。
2. **原 PDF 正文**：用于核对目录项对应的章节起始位置、正文范围和跨页关系，不得在无可靠依据时推翻原书目录。
3. **用户最新的明确要求**：用于确定输出形式、整理范围和其他个性化要求。
4. **[[通用要求]]及本规范中的格式规则**。
5. OCR 工具自动生成的 `#`、`##`、`###` 等标题标记。

> [!important] 原书目录是结构整理的最高标准
> OCR 生成的标题标记只作为待核验线索，不能直接视为正确结构，也不得用于推翻原书目录。章节名称、编号、顺序、层级和从属关系必须以原书目录为最高标准；原 PDF 正文、页眉、章节起始页和上下文只用于定位与复核。目录缺页、残损或无法可靠辨识时，才可根据原 PDF 正文暂定结构，并必须使用 Warning Callout 标明待核验部分。

### 3. 默认处理方式

- 默认新建结构优化后的文件，不直接覆盖 OCR 原文件。
- 默认保留为一个完整文件，不主动拆分章节；只有用户明确要求时才拆分。
- 默认只调整结构、排版和明确的 OCR 格式错误，不擅自改写知识内容。
- 若目录或正文无法可靠辨识，应保留原文并标注疑点，不得猜测章节名称或补造内容。
- 图片处理必须先判断资料类型：书籍类 OCR 图片 URL 默认保留，课件类 OCR 图片默认转写；具体遵循“七、公式、表格、图片与题解”。

## 二、优化前必须完成的检查

### 1. 完整阅读规范与来源

开始编辑前必须：

1. 完整阅读[[通用要求]]。
2. 读取待优化的 OCR Markdown 文件。
3. 查找并读取原书目录；目录可能位于 Markdown 前部、原 PDF 的目录页或单独的目录文件中。
4. 原 PDF 可用时，对照目录页、章节首页、页码及正文顺序进行复核。
5. 记录源文件的章节数、目录项数、图片数、表格数、公式块数和现有标题数，作为优化后的完整性核对基线。

### 2. 建立目录映射表

正式修改正文前，应先整理原书目录映射。推荐格式如下：

| 原书层级 | 原书编号 | 原书标题 | 起始页 | 优化后格式 |
|---|---|---|---|---|
| 章 | 第1章 | 章节名称 | 1 | `# 第1章 章节名称` |
| 节 | 1.1 | 节名称 | 1 | `## 1.1 节名称` |
| 正文内容分组（目录映射后补充） | 无或题型一 | 栏目名称 | 5 | 内容充分时使用 H2，否则使用加粗段落标签 |

目录映射表用于确认以下内容：

- 章、节的数量是否完整。
- 编号与名称是否和原书一致。
- 正文出现顺序是否与目录一致。
- OCR 是否漏掉、重复或误识别目录项。
- 哪些 `#` 是真正标题，哪些只是 OCR 伪标题。

### 3. 目录缺失时的处理

如果 OCR 文件中没有完整目录：

1. 优先从原 PDF 的目录页提取。
2. 再根据章节首页、页眉、页码及连续编号交叉核对。
3. 无法确认的标题只保留为普通文本或加粗标签。
4. 在相应位置加入 Warning Callout，说明目录缺失或层级尚未核验。

> [!warning] 禁止凭空重建目录
> 没有可靠来源时，不得仅根据字体大小、OCR 自动标题或个人理解推断完整目录。

## 三、标题层级重建规则

### 1. 标题层级上限

最终文件只使用 H1、H2、H3：

| Markdown 层级 | 用途 | 示例 |
|---|---|---|
| H1 | 前言、目录、章、原书节等主要模块；同一文件允许多个 H1 | `# 第1章 极限、函数与连续`、`# 1.2 范例解析与精讲` |
| H2 | H1 下的正式节或题型、专题等内容分组 | `## 1.1 竞赛要点与难点`、`## 题型一：函数极限` |
| H3 | H2 下的方法、情形或其他进一步细分 | `### 1. 利用基本极限` |
| 加粗标签 | 不足以独立成节的题型、方法、步骤、定理、例题组等小范围标签 | `**方法一：利用基本极限**` |

- 一个文件可以有多个 H1，每个 H1 对应一个主要模块；不再设置与文件名相同的唯一 H1，书名、章名只作为 frontmatter `title` 或正文引言。
- 完成原书目录映射后，应继续审查每个 H1 的正文；只要存在清晰、稳定且内容充分的分组，就应使用 H2 细分，不因该分组未列入原书目录而一律降为加粗标签。
- 允许使用 H3，但必须有原书目录、章节首页或正文结构等可靠依据，不得仅按 OCR 样式推断。
- 不使用 H4、H5、H6 或更深标题；原书层级超过 H3 时，用加粗标签、列表等非标题结构承载，并保留原编号与从属关系。
- 不允许标题跳级。
- H2、H3 本身已经是小标题，不再额外添加加粗标记；应写成 `## 题型一：函数极限`，不得写成 `## **题型一：函数极限**`。
- 书名页、出版社、作者、编委会等信息不得各自误设为 H1。

### 2. H2 内容细分原则

> [!important] 目录映射完成后继续细分 H2
> 原书目录决定 H1、H2 及原有章节的名称、编号、顺序和从属关系；完成目录结构更新后，还必须根据每个 H1 的实际内容判断是否需要 H2。只要 H1 下存在两个或以上可明确区分的知识主题、题型组、方法组或内容板块，就应使用 H2 组织，而不是把全部内容平铺在同一个 H1 下。

可以依据正文建立 H2 的情形包括：

1. H1 下存在两个或以上并列主题，每个主题都有连续正文、公式、例题或论证支撑。
2. OCR 中的题型、专题或方法组虽然未列入原书目录，但能够概括随后一组完整内容，并与相邻分组保持平行；题型或专题通常设为 H2，其下的方法或情形通常设为 H3。
3. 原书目录只列到章级，正文中却存在明显、稳定且可由章节首页、版式或内容转换确认的分组。
4. 一本书已按章拆分为独立 Markdown 文件时，章名作为文件标题（frontmatter `title`），原书节作为 H1；应继续根据各 H1 的正文内容建立 H2。

H2 标题必须忠实概括已有正文，不得新增知识范围或假称为原书目录项。单个例题、单条公式、解答、注释、临时步骤、只有一两句话的标签，以及不能概括后续内容的 OCR 大字，不得单独设置为 H2。

按章拆分文件时推荐结构：

```markdown
# 1.2 范例解析与精讲

## 题型一：函数极限

### 1. 利用基本极限

正文与例题。

### 2. 利用等价无穷小

正文与例题。

## 题型二：数列极限

正文与例题。
```

因此，按章拆分的书籍文件统一优先采用“原书节 H1—题型或专题 H2—方法或情形 H3”的结构；章名作为文件标题（frontmatter `title`），不再单独设置与文件名相同的 H1。后续同类内容以此类推，标题最多到 H3。

### 3. 有“章—节”目录的书籍

当原书目录包含“章—节”两级时，统一映射为：

```markdown
# 第1章 章标题

## 1.1 节标题

### 题型一：题型名称

**1. 方法名称**
```

其中：

- “第1章”使用 H1。
- “1.1”使用 H2。
- 在整本书未按章拆分、H2 已用于原书节的结构中，节内内容充分且相互并列的题型或专题可使用 H3 进一步细分；由于标题最多到 H3，其下的方法、情形或步骤使用加粗段落标签。

### 4. 有三级目录的书籍

当原书目录在“章—节”下还列有正式小节时，第三级目录项使用 H3：

```markdown
# 第1章 章标题

## 1.1 节标题

### 1.1.1 小节标题
```

只有原书目录、章节首页或正文结构能够可靠证明其为稳定内容分组时，才可使用 H3。在整本书未按章拆分且 H2 已用于原书节时，内容充分并统领一组正文或例题的题型、专题可以使用 H3；按章拆分文件中，方法或情形位于题型 H2 下并统领相应内容时也应使用 H3。孤立步骤、例题和图题不得升级为 H3。

### 5. 没有章编号的书籍

若原书只有若干并列主题，没有“第几章”编号：

- 原书一级目录项使用 H1。
- 原书二级目录项使用 H2。
- 原书三级目录项使用 H3。
- 第四级及更深内容使用加粗段落标签、有序列表或 Callout。

### 6. 前置与附加内容

以下内容通常作为 H1 主要模块处理：

- 内容简介
- 前言
- 第一版前言、第二版前言
- 目录
- 附录
- 参考文献
- 索引
- 本书小结

书名页中的系列名、作者、出版社、出版地、版次、ISBN 等应整理到“书目信息”模块中，不得把每一项设置成独立标题。

### 7. 标题文字要求

- 尽量保留原目录中的编号和标题原文。
- 只修复明确的空格、全半角、错别字或 OCR 粘连问题。
- 对无法确认的文字使用 Warning Callout 说明，不静默改写。
- 同级标题保持统一格式，例如不要混用“第1章”“第一章”和“Chapter 1”。
- 标题中不放完整题干、长公式、解答过程或页码点线。

## 四、OCR 伪标题的识别与处理

### 1. 常见伪标题

OCR 经常把以下内容错误识别为标题：

| 误识别内容    | 错误示例              | 正确处理                      |
| -------- | ----------------- | ------------------------- |
| 书名页信息    | `# 科学出版社出版`       | 普通文本或书目信息字段               |
| 题型标签     | `# 题型一、函数极限`      | 按章拆分文件中，能统领 H1 下完整内容组时设为 H2，如 `## 题型一：函数极限` |
| 方法名称     | `## 1. 利用基本极限`    | 位于题型 H2 下并统领相应内容时设为 H3，如 `### 1. 利用基本极限` |
| 题目或例题    | `### 例1.1 求极限`    | 普通例题段落                    |
| 解答起始语    | `##### 解 先求偏导数`   | `**解**：先求偏导数……`           |
| 注释       | `##### 【注】……`     | `**注**：……` 或 Note Callout |
| 定理正文     | `##### 定理4.1 设……` | 加粗定理名并保留完整正文              |
| 公式或编号    | `# 4. 曲线的渐近线`     | 结合目录与正文判断；能稳定统领内容组时使用相应 H2/H3，否则改为加粗标签 |
| 图题、页眉、页码 | `## 图3.2`         | 图示文字说明或普通图题               |

### 2. 判断目录标题与内容细分标题

原书目录标题只有同时满足以下条件时，才应优先认定：

1. 能在原书目录中找到对应项，或能在章节首页可靠确认。
2. 编号与前后章节连续。
3. 标题内容能概括随后一段正文，而不是题干、解答或公式的一部分。
4. 层级与相邻目录项一致。
5. 标题位置与原书页码、章节起始位置基本对应。

内容型 H2 不要求出现在原书目录中，但应同时满足以下条件：

1. 是某个 H1 的直接下级，用于细分该 H1 的章节内容。
2. 能概括一组连续且内容充分的正文、公式、例题、题型或方法，而不是只对应单个条目。
3. 与同一 H1 下的相邻 H2 处于相同抽象层级，并具有稳定、并列的分组关系。
4. 标题文字来自原文中的可靠表述，或是对已有内容的忠实概括，不扩大、不补造知识范围。
5. 不是例题名、解答起始语、注释、临时步骤、孤立公式、图题或只有一两句话的短标签。

目录标题若只满足前述一两项，不应直接保留 OCR 给出的 `#`；内容型 H2 若不能同时满足上述分组条件，也应降级为加粗标签或普通正文。

### 3. 错误标题的降级方式

根据内容性质选择处理方式：

1. 题型或专题：在按章拆分文件中能够统领 H1 下内容组时设为 H2；其下的方法或情形能够统领相应内容时设为 H3。不能统领后续内容的孤立名称才降级为加粗段落标签或普通正文。
2. 定义、定理、核心结论：使用块引用，并加粗名称。
3. 注释、提醒、OCR 疑点：使用 Obsidian Callout。
4. 例题名称：使用 `**例 1.1**：`，不设为标题。
5. 解答起始：使用 `**解**：`，并保持解答紧随题目。
6. 图题或表题：改为普通说明文字。
7. 页眉、页脚、重复书名和孤立页码：确认不承载知识信息后删除。

## 五、推荐的文件整体结构

### 1. 标准模板

```markdown
---
title: 书名
course: 课程或主题
tags:
  - 主题
  - OCR整理
created: YYYY-MM-DD
source:
  - "原始文件相对路径"
---

> 用两至三句话说明资料来源、覆盖范围与结构优化目的。

# 主要内容

- 第1章 章标题
- 第2章 章标题

---

# 书目信息

保留作者、出版社、版次、ISBN 等必要信息。

---

# 前言

完整保留前言正文。

---

# 目录

完整保留原书目录及原页码。

---

# 第1章 章标题

## 1.1 节标题

正文。

### 题型一：题型名称

正文。

**方法一：方法名称**

**例 1.1**：题目。

> [!answer]- 答案
> 解答与解析。

---

# 本书小结

总结覆盖范围；新增总结必须明确标注为 AI 补充。
```

### 2. 原目录的保留方式

- 原书目录不得被新的“主要内容”列表替代。
- “主要内容”用于概览，“目录”用于忠实记录原书章节与页码。
- 可修复目录中的 OCR 错行、断行和点线混乱，但不得删除页码或合并不同目录项。
- 如需增加 Obsidian 跳转链接，应保留原目录文字，并确保链接目标真实存在。

### 3. 大型书籍的处理

- 单文件过大时仍先完成完整目录映射，再决定是否拆分。
- 未经用户明确要求，不主动把一本书拆成多个文件。
- 用户要求拆分时，按章建立文件，并创建一份总目录笔记。
- 拆分后的章节文件应通过 `related` 和正文 wikilink 相互连接。

## 六、正文与知识信息保留要求

### 1. 零丢失原则

结构优化不得删除或概括替代以下内容：

- 定义、定理、性质、结论及成立条件。
- 公式、符号、变量限制和完整推导。
- 例题、练习题、真题、答案和解析。
- 表格、代码、注释和引用。
- 图片中承载的图形关系、坐标、数值、趋势和结论；书籍类 OCR 图片通过原 URL 保留，课件类图片通过完整转写保留，具体按“七、公式、表格、图片与题解”执行。
- OCR 无法可靠辨识但仍可能有意义的原文片段。

允许删除的内容仅限于经确认不承载知识信息的重复页眉、孤立页码、装饰性元素，以及按[[通用要求]]必须删除或脱敏的无关隐私信息。

### 2. 正文顺序

- 原则上按照原书页序和目录顺序排列。
- OCR 将跨页段落打断时，可以合并被错误分割的同一自然段。
- OCR 将题干与解答错位时，可以恢复原书顺序，但必须核对题号与上下文。
- 不得为了“更好理解”任意移动公式、题目或证明，导致引用关系改变。

### 3. OCR 不确定内容

对于乱码、公式残缺、图中标记模糊或原文矛盾，使用以下格式：

```markdown
> [!warning] OCR 内容待核验
> 此处原文或公式无法可靠辨识，已保留当前 OCR 结果，需对照原 PDF 复核。
```

不得通过删除、猜测或自行补全来隐藏不确定性。

## 七、公式、表格、图片与题解

### 1. 数学公式

- 行内公式使用 `$...$`，独立公式使用 `$$...$$`。
- 只修复明确的 LaTeX 定界符、命令、括号和上下标错误。
- 不得仅凭常识改变原公式的数学含义。
- 标题中误混入的公式应移回正文，并保持与前后文字的逻辑关系。

### 2. 表格

- 表格统一使用 Obsidian 原生 Markdown 管道表格。
- OCR 把表格拆成散乱文本时，应按原表的行列关系重建。
- 无法确认合并单元格或列关系时，应说明疑点，不得猜测。

### 3. 图片

> [!important] 图片规则按资料类型区分
> 本节是 OCR 优化任务对[[通用要求]]中“最终知识笔记完全去图片化”规则的专项调整。必须先判断来源属于书籍类还是课件类，再采用对应处理方式；用户最新的明确要求始终优先。

#### （1）书籍类 OCR 图片 URL

书籍类包括教材、辅导书、习题集、竞赛教程、论文集等具有连续页码、章节目次和出版物结构的资料。对于这类资料中由 PaddleOCR、MinerU 等工具生成的大量外部图片 URL：

- 默认原样保留 OCR 输出中的图片 URL、Markdown 图片语法或 HTML `<img>` 标签，不下载、不逐图查看、不转写、不描述、不重绘，也不因“去图片化”要求而删除。
- 图片 URL 及其所在位置视为原始内容的一部分，不得擅自改写、缩短、替换或调整顺序。
- 只有用户明确要求“转写图片”“处理图片”“去图片化”或指定某些图片需要识别时，才逐图查看并转为文字、LaTeX、Markdown 表格、代码块或 Mermaid。
- 用户仅要求“优化 OCR”“整理结构”或“按目录拆章”时，不自动触发书籍图片转写。

#### （2）课件类 OCR 图片

课件类包括 PPT、PPTX、课程讲义式 PDF、逐页幻灯片导出文件及其他明显按授课页面组织的资料。对于课件类 OCR 中的图片：

- 默认逐图查看并完整转写图片承载的知识信息，不因图片数量较多而跳过。
- 函数图像、几何图、统计图等转为完整文字描述；能够可靠重构的结构图使用 Mermaid。
- 公式图、表格图和代码图分别转为 LaTeX、Markdown 管道表格和注明语言的代码块。
- 装饰图应注明“该图为装饰图，不增加新的知识信息”，然后移除图片本身。
- 转写完成后移除对应图片嵌入、HTML 图片标签、外部图片 URL 和 MinerU 图片路径，确保知识信息已经由 Obsidian 原生内容完整接替。

#### （3）资料类型判断

- 有书名、作者、出版社、ISBN、连续页码、完整目录和章—节结构时，优先判断为书籍类。
- 有课程名、授课单元、每页独立标题、项目符号式内容和明显幻灯片版式时，优先判断为课件类。
- 书籍 PDF 被拆成多个章节 Markdown 文件后，仍按书籍类处理；课件导出为 PDF 后，仍按课件类处理。
- 无法可靠判断时，应继续核对来源文件与正文结构；仍不能确定则暂时保留图片 URL，并使用 Warning Callout 标明“资料类型待核验”，不得直接删除图片或猜测转写。

### 4. 题目与答案

> [!important] 所有 Markdown 文件的答案是否折叠，取决于内容组织形式
> 本条适用于所有 OCR 优化后的 Markdown 文件，并与[[通用要求]]保持一致。当且仅当内容采用“一题一答案”形式时才遮盖答案；章节末尾、文件末尾或独立模块中整节、整篇均为参考答案的答案汇编，不使用折叠 Answer Callout，以免大量内容一次性按 Callout 渲染导致 Obsidian 卡顿。

- 题干必须完整保留在正文中。
- **一题一答案形式**：当一道题的答案、解答或解析紧随该题题干出现时，使用 `> [!answer]-` 折叠 Callout；Callout 内每一行都必须带 `>`。
- **答案汇编形式**：标题为“参考答案”“答案与解析”“训练全解与分析”等的章节末尾、文件末尾或独立模块，如果整节、整篇内容都是对前文或其他位置题目的参考答案、解答和解析，则直接以普通正文展示，不在整体外包裹 `> [!answer]-`，也不为其中每题逐一添加折叠 Callout。
- 答案汇编必须保留原题号、子题号、方法编号、推导步骤以及与对应原题的关系；不得因取消折叠而合并、删减或打乱答案。
- 只有模块中重新出现完整题干，并形成“单题题干—该题答案”的连续结构时，才对该题答案单独使用折叠 Answer Callout。
- 手写答案或 OCR 识别答案必须标明来源与待核验状态，不得默认视为标准答案。

## 八、推荐编辑流程

### 1. 第一阶段：建立基线

1. 复制源文件，确定新文件名。
2. 统计原文件行数、字符数、标题数、图片数、表格数和公式块数。
3. 提取原书目录并建立目录映射表。
4. 标记章节起点、节起点和疑似伪标题。

### 2. 第二阶段：重建结构

1. 添加合规 YAML frontmatter。
2. 按目录映射设置各主要模块的 H1；同一文件可以有多个 H1，不再设置与文件名相同的唯一 H1。
3. 整本书保存在一个文件中时，将章级目录项设为 H1、节级目录项设为 H2。
4. 书籍已按章拆分时，章名作为文件标题（frontmatter `title`），原书节设为 H1。
5. 按章拆分文件完成目录映射后，逐个检查 H1，将题型或专题等清晰、稳定且内容充分的并列分组设为 H2。
6. 在按章拆分文件中，将题型 H2 下能够统领相应内容的方法或情形设为 H3；在整本书文件中，则根据已有标题层级使用 H3，且始终不超过 H3。
7. 将不能统领完整内容组的单个题型、方法、步骤等改为加粗标签、列表或其他非标题结构。
8. 将解答、注释、定理、图题等伪标题恢复为对应正文格式。
9. 按原书目录检查章节顺序和编号连续性，并确认内容型 H2 未改变原书章节顺序或知识范围。

### 3. 第三阶段：清理格式

1. 修复明确的段落断行和多余空行。
2. 修复明确的 LaTeX 与 Markdown 语法错误。
3. 重建表格，并按资料类型处理图片：书籍类 OCR 图片 URL 默认保留，课件类图片逐图转写。
4. 按题解组织形式处理答案：一题一答案时将答案与解析放入折叠 Callout；整节或整篇“参考答案”“答案与解析”“训练全解与分析”等答案汇编改为普通正文，不整体或逐题折叠。
5. 课件类文件删除已经完成转写的 HTML 图片标签、图片路径和无知识信息的装饰元素；书籍类保留 OCR 图片 URL，除非用户明确要求处理。

### 4. 第四阶段：逐项核对

1. 逐章核对目录项与正文标题。
2. 按页或内容块核对题目、公式、答案、表格和图片。
3. 比较优化前后的内容量，调查异常减少的原因。
4. 在 Obsidian 阅读模式中检查 YAML、标题、公式、表格、Callout 和 wikilink。

## 九、输出文件要求

### 1. 文件命名

默认命名方式：

```text
原文件名-结构优化.md
```

例如：

```text
全国大学生数学竞赛解析教程（上册）-结构优化.md
```

- 不覆盖原 OCR 文件。
- 文件名应简洁，必要时去掉下载站点、随机编号和冗余转换器后缀。
- 如果用户指定文件名，以用户指定名称为准。

### 2. 来源记录

YAML 中的 `source` 应记录原始 PDF 和 OCR Markdown 的相对路径。正文引言应说明该文件是结构优化版本，并明确原文件仍被保留。

### 3. 新增内容标记

凡原书没有、由 AI 增加的说明、总结或辅助解释，都必须明确标注“AI 补充”，不得与原文混写。

## 本章小结

| 方面 | 核心要求 |
|---|---|
| 结构依据 | 以原书目录和原 PDF 为准，不盲信 OCR 的 `#` |
| 标题层级 | 允许多个 H1；按章拆分时原书节用 H1、题型或专题用 H2、其下方法或情形用 H3；标题不加 `**`；禁止 H4 及更深标题 |
| 内容完整性 | 调整结构不得删减正文、公式、题目、答案、表格和图示信息 |
| 答案展示 | 一题一答案时折叠；整节或整篇答案汇编直接展示 |
| 不确定内容 | 保留 OCR 结果并标记待核验，不猜测、不补造 |
| 图片处理 | 书籍类 OCR 图片 URL 默认保留；课件类图片默认逐图转写；用户明确要求优先 |
| 输出方式 | 新建结构优化文件，不覆盖原 OCR 文件 |
| 最终验证 | 对照目录、原文和 Obsidian 阅读模式逐项检查 |

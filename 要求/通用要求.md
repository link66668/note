# 通用要求

> 本文件是本 Obsidian 仓库始终生效的通用基线。创建、转换、整理或修改任何 Markdown 笔记时，首先保证 Obsidian 原生语法正确、文件结构清晰、命名统一和图片信息完整转写，再处理内容润色与其他格式细节。

> [!important] 通用要求与专项要求
> 复习计划、总复习、真题合订、OCR 优化等专项要求按照各自既有触发条件启用。专项要求启用后，冲突部分以专项要求为准，无冲突部分继续遵循本文件；用户最新的明确要求始终具有最高优先级。

> [!important] 内容与隐私底线
> 整理、转换、改写或美化不得丢失、弱化或概括替代来源中的有效信息。与知识内容无关的个人隐私必须删除或脱敏；正文确实不足时，只能在不违背用户范围和专项要求的前提下补充，并明确标注“AI 补充”。

## 主要内容

- Obsidian 原生语法
- 文件与笔记结构
- 文件命名规则
- 图片信息转写
- Frontmatter、链接与标签
- 内容完整性、隐私与不确定信息
- 公式、表格、代码与正文排版
- 算法和特殊内容
- 题目与答案整理
- 编辑流程与发布检查

## 一、Obsidian 原生语法

> [!important] Obsidian 是唯一渲染标准
> Markdown、YAML、链接、表格、公式、代码块、Callout 和 Mermaid 均以 Obsidian 核心功能能够直接解析和阅读模式正常渲染为最终标准。其他编辑器或 Markdown 方言只作为辅助参考。

1. **只使用核心语法**：使用 Obsidian 支持的 Markdown、YAML Properties、wikilink、Callout、MathJax/LaTeX、管道表格、代码围栏和 Mermaid。
2. **默认不依赖插件语法**：除非用户明确要求，不使用 Dataview、Templater、Admonition、JS Engine、MDX、Pandoc 或 GitHub 专用提示框代替核心语法。
3. **链接分类明确**：库内文件使用 wikilink；外部网页使用标准 Markdown 链接。
4. **提示使用 Callout**：使用 `> [!note]`、`> [!tip]`、`> [!warning]`、`> [!answer]-` 等 Obsidian Callout，不使用自定义 HTML 提示框。
5. **图形与公式受 Obsidian 能力约束**：不引入外部脚本、在线图床或浏览器专用组件。
6. **最终必须验证**：至少检查 Properties、标题、列表、表格、公式、Callout、wikilink、代码块和 Mermaid。

## 二、文件与笔记结构

### 1. 仓库文件结构

- 课程文件按科目文件夹归类，具体遵循[[仓库目录结构指南要求]]。
- 直接位于仓库根目录的科目文件夹表示当前时期；已结束时期的科目整体归档到“大一上”“大二下”等时期文件夹。
- 每个科目的原始资料统一存放在该科目的 `原件` 文件夹。
- 要求类 Markdown 文件统一存放在仓库根目录的 `要求` 文件夹。
- `AGENTS.md`、`CLAUDE.md` 和 `README.md` 作为仓库级入口文件保留在根目录。
- 移动或重命名文件后，必须检查 wikilink、frontmatter `source`、`related`、课程索引、脚本路径和 Obsidian 工作区记录。

### 2. 单篇笔记结构

除用户或已启用专项要求另有规定外，笔记按以下顺序组织：

1. YAML frontmatter。
2. 唯一 H1，且与 frontmatter `title` 完全一致。
3. 引言引用，用 2～3 句话说明主题、来源和用途。
4. `## 主要内容`，使用连续的 `-` 无序列表概览核心内容。
5. H2 主要模块，通常使用“一、二、三……”编号，模块之间用 `---` 分隔。
6. H3 模块内部要点，通常使用“1. 2. 3.”编号。
7. H4 仅在 H3 下确需继续细分时使用。
8. `## 本章小结`或与资料类型匹配的小结标题。
9. `## 课后作业`为可选模块。

### 3. 标题层级

| 层级 | 用途 | 默认编号 |
|---|---|---|
| H1 | 文件唯一标题 | 不编号 |
| H2 | 主要模块 | 一、二、三…… |
| H3 | 模块内部要点 | 1. 2. 3. …… |
| H4 | H3 下的必要细分 | （1）（2）（3）……或简短标题 |

- 允许使用 H4，但只用于 H3 下确有层级意义的细分内容，不得仅为强调文字而滥用。
- 不允许使用 H5、H6 或更深标题，也不允许标题跳级。
- 标题应简洁、准确、平行，不把完整题干、长公式、解答过程或无信息量措辞写入标题。
- OCR 产生的标题必须结合来源结构核验，不能直接视为正确层级。

## 三、文件命名

| 文件类型 | 命名规则 | 示例 |
|---|---|---|
| 课程章节笔记 | `n.a 主题.md` | `2.1 古典密码体制.md` |
| 原始资料 | 保留原始文件名，并放入科目 `原件` | `第2章 古典密码体制(1).pdf` |
| 一般主题笔记 | 简洁、唯一的主题短语 | `通用要求.md` |
| 专项汇总文件 | 遵循已启用专项要求或用户指定名称 | `总复习.md` |

- `n` 表示章号，`a` 表示该章内按课件顺序排列的节号。
- 文件名应能望文知义，避免无意义后缀、重复词和无法辨识的缩写。
- 避免 Windows 与 Obsidian 非法字符：`/ \ : * ? " < > |`。
- 不覆盖内容不同的同名文件；版本确有必要时保留日期、版次或可辨识版本号。

## 四、图片信息转写

> [!important] 最终知识笔记完全去图片化
> 最终 Markdown 笔记不得保留 Obsidian 图片嵌入、Markdown 图片、HTML 图片标签、外部图片链接或 MinerU 图片路径。图片承载的知识必须由 Mermaid、管道表格、LaTeX、代码块或完整文字描述接替。

禁止残留：

- `![[图片名.png]]`
- `![说明](图片地址)`
- `<img ...>`
- `images/...`、`../images/...`

### 1. 逐图处理顺序

1. **先查看原图**：不得跳过图片，也不得只写“见图”“如下图所示”。
2. **结构图原生重构**：流程图、E-R 图、思维导图、状态图、时序图、层次图和关系图能够可靠还原时，转换为 Mermaid。
3. **专用格式重构**：表格转为 Markdown 管道表格，公式转为 LaTeX，代码和终端输出转为注明语言的代码块。
4. **无法可靠重构时完整描述**：说明对象、布局、关系、方向、坐标、数值、趋势、标注和结论，并标出无法确认之处，不得猜测。
5. **装饰图明确判断**：封面、图标、人物照片或背景装饰不增加知识时，注明“该图为装饰图，不增加新的知识信息”，然后移除图片。
6. **核对数量与信息**：确认每张来源图片都有对应处理结果，且最终文件没有图片语法和路径。

### 2. Mermaid 兼容要求

- 流程图使用 `flowchart TD` 或 `flowchart LR`，判断分支保留“是/否”等标签。
- E-R 图优先使用 `erDiagram`，明确实体、主要属性、主键、外键和基数；关系说明使用双引号。
- `erDiagram` 的实体和属性标识符使用 ASCII 字母、数字与下划线，中文放在注释中；避免把 Mermaid 关键字直接作为标识符。
- 思维导图使用 `mindmap`；版本不兼容时改用分层 `flowchart`。
- 时序关系使用 `sequenceDiagram`，状态转换使用 `stateDiagram-v2`。
- Mermaid 节点保持简洁，详细定义、公式和例题放在正文。
- 重绘必须忠于原图；无法确认的连线、方向、属性或基数改用文字说明，不得臆造。

## 五、Frontmatter、链接与标签

### 1. Frontmatter

所有笔记顶部必须包含 YAML frontmatter：

| 字段 | 必填范围 | 要求 |
|---|---|---|
| `title` | 所有笔记 | 与正文 H1 完全一致 |
| `tags` | 所有笔记 | 2～5 个，优先使用已有标签 |
| `created` | 所有笔记 | `YYYY-MM-DD` |
| `course` | 课程笔记 | 所属科目 |
| `source` | 来源整理笔记 | 从仓库根目录开始的相对路径，通常指向科目 `原件` |
| `related` | 可选 | wikilink 列表 |

```yaml
---
title: 3.1 密码学基础——Shannon 理论
course: 现代密码学
tags:
  - 密码学
  - Shannon理论
created: 2026-08-02
source:
  - "现代密码学/原件/第3章 密码学基础.pdf"
related:
  - "[[2.1 古典密码体制]]"
---
```

### 2. 链接与标签

- 库内链接统一使用 `[[笔记名]]` 或 `[[路径/笔记名|显示文本]]`。
- 拆分的系列笔记在 `related` 和正文首尾互相连接。
- 外部网页使用 `[文本](URL)`。
- 标签从课程、主题和资料类型等稳定维度选择，避免重复、过细或无意义的新标签。

## 六、内容完整性、隐私与不确定信息

### 1. 正文零丢失

必须完整保留：

1. 定义、定理、性质、结论、适用范围、条件、限制、例外和注意事项。
2. 符号含义、参数约束、公式、等式变形、证明、计算步骤、中间结果和最终结果。
3. 算法输入输出、初始化、分支、循环、状态更新、终止条件、复杂度和实现细节。
4. 例题、练习、数据、表格、代码、引用、链接、注释和图片承载的信息。
5. OCR 错误、原文矛盾、模糊内容和暂时无法核验的信息。

- 可以合并等价重复、调整顺序或精炼语言，但每项来源信息都必须有明确对应，限定词、因果关系和推导链不得消失。
- 只修复有可靠依据的 OCR、Markdown 和 LaTeX 语法错误，不擅自改变公式含义或补造结论。
- 调整段落位置后必须保持原意、引用关系、推导关系和题目—答案对应关系。
- 新增说明与原文明确区分；AI 新增内容标注“AI 补充”。
- 整理完成后按页、标题或内容块对照来源，检查漏页、漏段、漏题、漏表、漏图、漏代码和异常重复。

### 2. 不确定内容

> [!warning] 待核验内容
> 无法可靠辨识、来源矛盾或修复依据不足时，保留可辨识原文并说明疑点，不得通过删除或猜测掩盖不确定性。

### 3. 隐私处理

- 删除或脱敏与知识无关的姓名、证件号、学号或工号、电话、私人邮箱、住址、定位、账号、银行卡号、车牌、个人二维码、签名等可识别信息。
- 作者署名、资料来源、案例必要条件等确有知识作用的信息按最小化原则保留。
- 删除会破坏题意时，使用“某教师”“某学生”“某机构”等泛化称谓。
- 密码、验证码、访问令牌、私钥等认证凭据一律不保留，只说明其类型或作用。
- 无法判断知识价值时优先保护隐私，但不得破坏必要的知识语义。

## 七、公式、表格、代码与正文排版

### 1. 数学公式

- 行内公式使用 `$...$`，独立公式使用 `$$...$$`，定界符必须成对。
- 定界符内侧不留空格：`$x$`，不要写成 `$ x $`；`$$公式$$`，不要写成 `$$ 公式 $$`。
- 必须主动搜索并修复定界符内侧空格，只删除公式首尾多余空格，不机械删除公式内部有意义的空格或命令间距。
- OCR 把 `$` 误识别为成对 `&` 时，只有对照来源确认其为公式后，才把 `& x+y &` 改为 `$x+y$`。
- 普通文本中的 `&`、HTML 实体 `&amp;`，以及 `aligned`、`align`、`array`、`matrix`、`cases` 中用于列对齐的 `&` 必须保留；禁止全局替换。
- 同余和模运算使用标准命令，例如 `$a \equiv b \pmod{m}$`。
- 复杂公式独立成行，公式前后留一行；需要渲染的公式不放入代码块或行内代码。
- 修复只针对渲染语法，不改变数学含义；无法确认时用 Warning Callout 标记。

### 2. 表格

- 所有表格使用 Obsidian 原生 Markdown 管道表格，不使用 HTML、Dataview、图片或代码块模拟表格。
- 第一行为表头，第二行为分隔行；每行单独占行，单元格使用 `|` 分隔。
- 单元格中的竖线写为 `\|`；表格前后保留一行，表格内部不插入空行。
- HTML 合并单元格改为独立列；无法表达的合并关系用空单元格和文字说明保留。
- 大表格按知识主题拆分，单元格保持简洁，不堆放长段落、复杂 HTML 或多层列表。

```markdown
| 字段一 | 字段二 | 字段三 |
|---|---|---|
| 内容一 | 内容二 | 内容三 |
```

### 3. 代码、强调与 Callout

- 代码、终端输出、明文、密文和密钥串使用注明语言的代码块；短内容使用行内代码。
- 定义、定理和核心结论使用块引用，必要时加粗名称。
- 示例统一写为 `**例**：`或`**例 1.1**：`。
- 延伸思考使用 `> **思考**：`。
- 疑点使用 Warning Callout，说明使用 Note Callout，答案使用折叠 Answer Callout。

### 4. 段落、列表与分隔

- 同一自然段中间不插入空行；连续空白行最多保留一行。
- 空行只用于分隔段落、标题、列表、引用、公式、表格和代码块等独立结构。
- `## 主要内容`使用 `-` 无序列表，列表项之间不插入空行。
- “包括以下几种”“分为几类”“执行步骤”等列举内容使用 `1.`、`2.`、`3.` 有序列表。
- 列表项说明需要换行时使用两个空格后换行，不在同一列表项中插入空段落。
- H2 主要模块之间使用 `---`，不得用连续空行制造视觉间距。

## 八、算法与特殊内容

### 1. 算法说明

> [!important] 算法不得只转写不解释
> 原始算法、公式、流程图、代码或伪代码必须完整保留或等价重构；解释只能补充，不能替代或删减原始内容。

算法说明根据来源与任务范围尽量覆盖：目标与场景、输入输出与前置条件、符号与数据结构、初始化、逐步执行、循环与分支、状态变化、终止条件、结果解释、正确性原理、复杂度、边界、失败条件和完整示例。来源未说明且无法可靠推导的内容明确写“来源未说明”或“无法确认”，不得猜测。

### 2. 密码学内容

- 优先按照“密码体制或定义 → 符号与参数 → 加密与解密 → 性质或安全性 → 示例与应用”组织。
- 密钥、明文、密文、初始向量或随机数、轮函数、状态结构、加解密方向和数据依赖必须明确。
- 密码体制、定义和定理使用块引用；普通讲解不必全部加引用。

## 九、题目与答案整理

### 1. 题目资料范围

- 用户指定目录或已启用专项要求划定的目录即整理范围，必须遍历其中全部资料，不按 PDF、Markdown、HTML、模拟题、答案页或知识总结等文件类型跳过。
- PDF 与其 OCR 转写文件视为同一资料的两个来源，应共同写入 `source`，避免建立内容重复的正式笔记。
- 来源只包含残缺题干或要点式记录时，如实保留并说明缺失范围，不补造题干、数据或答案。
- 题干中的条件、选项、公式、表格、图示信息和全部子问题必须完整保留。

### 2. 手写答案与原卷作答

- 手写答案、原卷作答、批改痕迹和 OCR 答案属于待核验参考，不默认视为标准答案。
- 明确标注“手写参考答案”“原卷作答”“批改标注”或“整理者核验”。
- 疑似错误时保留原答案，并用 Warning Callout 分别说明原卷内容与核验疑点；不静默修正或删除。
- 字迹、圈选、连线或步骤无法确认时写明“无法可靠辨识”或“尚未核验”，不得强行补全。
- 核验依据优先使用题干、完整计算、教材、课件和库内笔记；仍不能确认时保留不确定性。

### 3. 答案折叠

所有已有答案、解析、计算过程和核验结论统一放入默认折叠的 Answer Callout；题干和选项不得放入其中。Callout 内每一行，包括空行、列表、公式、表格和代码，都必须带 `>`。

```markdown
> [!answer]- 答案
> 答案正文。
>
> 多段解析继续保持在同一引用范围内。
```

- 来源没有答案时不得自行编造。
- Callout 标题注明答案性质和可信状态。
- 答案存在矛盾或模糊内容时，在 Callout 内或紧随其后增加 Warning Callout。

## 十、编辑流程与工具支持

### 1. 标准流程

1. 读取本通用要求、用户要求和已触发的专项要求。
2. 按[[仓库目录结构指南要求]]确认文件归属、原件位置和输出路径。
3. 读取完整来源，统计章节、题目、图片、表格、公式、代码和其他关键内容。
4. 先建立文件结构与标题映射，再整理正文；不边猜测边删除。
5. 逐图转写，修复明确的 OCR、Markdown 和 LaTeX 问题。
6. 对照来源逐页、逐标题或逐内容块检查信息完整性。
7. 在 Obsidian 阅读模式检查渲染，并完成发布前清单。

### 2. VSCode 支持

- VSCode 只是编辑工具，语法和渲染仍以 Obsidian 为准。
- 可使用 Foam、Markdown All in One、markdownlint、Markdown Preview Enhanced、YAML 和 Code Spell Checker 辅助编辑。
- 推荐 UTF-8、自动换行和 2 空格缩进；相关设置不得改变 Markdown、LaTeX 或 YAML 语义。
- wikilink 在 VSCode 中需要相应扩展才能跳转，未安装时仍是有效的 Obsidian 文本。

## 十一、发布前检查清单

### 1. 语法与结构

- [ ] 文件位于正确时期、科目或 `要求` 目录，根目录科目属于当前时期，原始资料位于科目 `原件`
- [ ] YAML 可解析，`title` 与唯一 H1 一致，tags 和日期完整
- [ ] 结构为“引言 → 主要内容 → H2/H3/H4 正文 → 小结”，无无效标题、标题跳级或 H5 及更深标题
- [ ] 全文只使用 Obsidian 核心可解析语法，并已在阅读模式验证
- [ ] wikilink、外部链接、`source` 和 `related` 目标正确

### 2. 内容与隐私

- [ ] 与来源逐页或逐内容块核对，无漏段、漏题、漏表、漏图、漏代码或异常重复
- [ ] 条件、限定词、变量含义、中间步骤、推导链和例外均已保留
- [ ] 调整顺序后原意、引用关系和题目—答案关系未改变
- [ ] OCR 疑点和原文矛盾已保留并标记，没有猜测或静默修正
- [ ] 无关隐私已删除或脱敏，凭据未进入最终笔记
- [ ] AI 新增内容已明确标注，且没有突破用户或专项要求范围

### 3. 图片、公式与表格

- [ ] 每张来源图片均已查看并转为 Mermaid、表格、公式、代码或完整文字描述
- [ ] 最终文件不存在图片嵌入、HTML 图片标签、外部图片链接或图片路径
- [ ] 公式定界符成对，无 `$ x $`、`$$ x $$` 等内侧空格
- [ ] OCR 的 `& 公式 &` 已按来源核验；LaTeX 对齐符 `&` 未被误改
- [ ] 所有表格均为原生管道表格，复杂表格已合理拆分
- [ ] Mermaid 忠于原图、语法兼容，无法确认的内容没有臆造

### 4. 题目、算法与排版

- [ ] 题干、选项、子问题和已有答案完整，答案使用 `> [!answer]-`
- [ ] 手写答案与原卷作答已注明来源和待核验状态
- [ ] 算法保留原始内容，并在任务范围内说明输入输出、步骤、状态、终止和结果
- [ ] 同一自然段没有多余空行，列表、代码块、公式和 Callout 没有断裂
- [ ] `## 主要内容`使用连续无序列表，列举内容使用适当有序列表

---

## 十二、本要求小结

| 优先事项 | 核心要求 |
|---|---|
| Obsidian 语法 | 以核心功能和阅读模式渲染为唯一标准 |
| 文件结构 | 根目录科目表示当前时期，历史科目按时期归档；原件进 `原件`，要求文件进 `要求` |
| 文件命名 | 简洁唯一，课程章节采用统一编号 |
| 图片转写 | 逐图处理，知识完整接替，最终完全去图片化 |
| 内容完整性 | 不丢失、不弱化、不猜测，疑点明确标记 |
| 公式与表格 | LaTeX 可渲染，管道表格原生兼容 |
| 题目与答案 | 题干完整，答案折叠，手写内容保持质疑 |
| 最终验证 | 对照来源并在 Obsidian 阅读模式完成检查 |

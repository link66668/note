# 真题合订编写要求

> 本要求适用于文件名（不含路径和 `.md` 扩展名）为 `真题合订` 的 Markdown 文件，用于把课程 `真题整理` 目录中的历年试卷题目按「章节 → 题型」汇总成一个可直接复习、按章刷题的真题合订文件。**理论上，当前课程任何一套试卷中的任何一道题都必须收录；若某道题无法划分到既有章节，则单独设立一个章节集中收录，不得省略。**同一道题（题干完全一致）在不同试卷中重复出现时，合并为一个条目并列标注全部来源；表述不完全一致的题目即使主题相同也不合并，分别列出。原卷为英文的题目统一译为中文。除用户另有明确要求外，`真题合订.md` 还必须遵循 [[通用要求]] 中的通用 Markdown、frontmatter、公式、表格、图片转写、内容保留及发布前检查规范。

## 主要内容

- 文件定位
- 触发条件与适用范围
- 章节归类规则
- 题型分类规则
- 题目收录与题干完整性
- 英文题翻译规则
- 来源标注规则
- 重复题合并规则（仅完全一致才合并）
- 跨章与综合题处理
- 未归类题目单独成章
- 答案折叠规则
- Markdown 结构模板
- 整理流程
- 发布前检查清单

---

## 一、文件定位

1. `真题合订.md` 是把课程 `真题整理` 目录中全部试卷、模拟题和复习资料里的题目，按「章节 → 题型」重新编排的**汇总文件**，供用户按章复习、按题型刷题。**理论上，当前课程任何一套试卷中的任何一道题都必须出现在合订中**：题目可以暂时无法归类、可以残缺、可以来源不确定，但不得被省略。
2. 与 `总复习.md` 的区别：`总复习.md` 以用户筛选出的**知识点**为主体；`真题合订.md` 只**汇总题目**，不展开知识点讲解，也不替用户答题。
3. 正文以题目为主体，避免加入与题目无关的处理过程说明、AI 工作日志或大段方法讨论。必要的归类说明（如跨章提示、重复题说明、要点式记录说明）可以保留。

---

## 二、触发条件与适用范围

1. 待创建、润色、整理、完善或修改的 Markdown 文件名（不含路径和 `.md` 扩展名）为 `真题合订` 时，自动套用本要求。
2. **文件名 `真题合订` 是本规则的自动触发条件。**文件名仅含“真题”或“合订”但不完全等于 `真题合订` 时，不自动套用；用户明确要求套用时除外。
3. 题目范围 = 课程 `真题整理` 目录内的全部 Markdown 文件中的题目。**理论上，当前课程任何一套试卷（正式试卷、模拟题、样题、答案页、复习资料、要点记录、回忆记录等）中的任何一道题都必须收录**；不得按文件类型跳过任何文件，也不得因题目残缺、无法归类、来源不确定或看似不重要而省略。
4. 章节依据 = 同课程 `笔记` 目录下的章节笔记文件（如 `1.1 计算机网络概述`、`2.1 应用层`），按笔记编号确定章节顺序与名称；笔记目录没有明确编号时，按课程实际章节体系排序。

---

## 三、章节归类规则

1. 每个课程章节使用一个 H1；真题合订允许有多个 H1，不再设置与文件名相同的唯一 H1。
2. 例如：
   - `# 一、第 1 章 计算机网络概述`
   - `# 二、第 2 章 应用层`
   - `# 三、第 3 章 运输层`
   - ……
3. 判断题目属于哪一章时，以题目主要考查对象、课程笔记内容和章节体系为依据，不以来源文件名分组。
4. 不按试卷或来源文件建立章节标题；来源文件只用于题内标注，不是分组依据。
5. 章节之间使用分隔线 `---`。
6. **无法归类的题目单独成章**：当某道题无法可靠划分到任何既有课程章节时（例如跨章综合且无明显主要章节、超出笔记章节体系、题意残缺难以判断所属章节），不得删除或省略该题，应在所有课程章节之后、`# 本章小结` 之前，**单独设立一个章节（H1）集中收录这些题目**，章节名称示例：`# 八、其他未归类题目`。该章节内部仍按题型排列（选择题、填空题、判断题、名词解释、简答题、计算题、综合题）；每道题应加 `> [!note]` 说明无法归类的具体原因，来源标注、题干完整性、答案折叠等规则与其他章节一致。若后续能确定章节，可移入对应章节。

---

## 四、题型分类规则

> [!important] 题型是章内第一分组依据
> 每章内部先按题型集中排列题目，不得以试卷或来源文件作为章内第一分组依据。

1. 每章内部按题型排列。默认题型顺序：**选择题 → 填空题 → 判断题 → 名词解释 → 简答题 → 计算题 → 综合题**。
2. 用户明确给出题型顺序（例如“选择、填空、简答、计算等”）时，以用户要求为准。
3. 来源已标注题型时以来源标注为准；来源未标注时按主要作答方式判断。
4. 一道题包含多个不同类型子问题且不可安全拆分时，归入“综合题”；可以安全拆分且各子问题分属不同章节时，可拆分到对应章节，并保留原题号说明。
5. 某章节没有某类题目时，不建立空分类标题。
6. 题型使用 H2 标题，例如 `## 1. 选择题`、`## 2. 填空题`；题目条目使用加粗编号（如 `**1.**`）。本专项采用较浅层级，通常不需要 H3；如确有必要可按 [[通用要求]] 使用 H3，但不得使用 H4 及更深标题。

---

## 五、题目收录与题干完整性

> [!important] 题干零删减
> 每道题的题干都必须完整保留：题干文字、小题编号、选项 A/B/C/D 及内容、数据数值、条件、公式（LaTeX 原样）、网络拓扑或场景描述。不得用考点名称、概括句或“略”代替题目。

1. 遍历 `真题整理` 目录中的全部 Markdown 文件，逐题收录，不得按文件类型跳过。
2. 题干必须完整；来源文件本身为要点式记录（例如只写了“NAT 的性质”而无完整题干）时，如实保留并注明“原卷为要点式记录”，不得编造完整题干。
3. 原题含图时，图片承载的信息应转写为文字、Mermaid 或原生表格；无法可靠转写时注明“原题含图，图中信息未在文字中保留”，不得猜测重绘。
4. OCR 疑似错误、数据矛盾、概率和不为 1 等情况原样保留，并使用 Warning Callout 标注疑点，不静默修正。
5. 隐私信息按 [[通用要求]] 删除或脱敏。
6. **英文题翻译**：原卷为英文的题目，题干、选项与英文说明文字统一译为中文；数据、数值、条件、公式（LaTeX 原样）、表格、代码与子题结构必须完整保留，不得因翻译丢失信息。技术术语使用规范译名（如进程、线程、信号量、死锁、银行家算法、页面置换、系统调用、时间片轮转等）；操作系统与软件专有名词（Windows、Linux、Unix、Android、FIFO、LRU、OPT、FCFS、PCB、MMU 等）保留原文。翻译确有不确定处，使用 Warning Callout 说明。

---

## 六、来源标注规则

1. 每道题都必须在题干处标注来源试卷，使用 wikilink：`（来源：[[试卷文件名]]）`。
2. 完全一致的重复题合并时，并列标注全部来源：`（来源：[[试卷A]]、[[试卷B]]）`；表述不完全一致的题目分别列出，各标注其所在试卷。
3. 不得只在题型标题处统一标注一次来源。
4. 无法从 `真题整理` 文件确认来源的题目，标注“来源未确认”，不得自行推断学年、试卷或分值。

---

## 七、重复题合并规则（仅完全一致才合并）

1. 同一道题（**题干完全一致**，即题意、条件、选项内容均相同；可忽略空白、填空下划线等卷面格式差异）在多份试卷中出现时，**合并为一个条目**，并在来源中并列标注全部试卷。
2. 表述不完全一致（措辞、参数、选项顺序或选项内容不同）的题目，即使考查主题相同，也视为不同题目，分别列出，不得合并。
3. 同一份试卷内部若出现两次相同题目，也合并为一个条目并列同一来源。
4. 不同试卷对同一题的答案不一致时，在同一折叠答案 Callout 内并列保留各来源答案，并追加 Warning Callout 说明矛盾，不擅自判定谁对谁错。

---

## 八、跨章与综合题处理

1. 一道题同时涉及多个章节时，归入**主要考查章节**。
2. 确有必要时可在另一相关章节用“见第 n 章对应条目”或 wikilink 提示，避免无说明地重复整道题。
3. 归类时可在题目前加 `> [!note] 章节归属说明` 简要说明跨章情况。
4. 若一道题同时涉及多个章节但**无法判断主要考查章节**，或经判断**不属于任何既有课程章节**，则按「三、章节归类规则」第 6 条，将该题收入“其他未归类题目”章节，并在题内注明原因，不得省略。

---

## 九、答案折叠规则

> [!important] 答案必须默认折叠
> 来源附有答案的题目，必须紧跟题干使用 Obsidian 折叠 Answer Callout：`> [!answer]-`。减号 `-` 表示默认折叠，避免读题时直接暴露答案。

1. 统一格式：`> [!answer]- 答案`，答案正文的每一行（含空行、列表、公式、表格与代码块）都必须添加 `>` 引用标记，确保全部内容位于同一个折叠 Callout 内。
2. Callout 标题应注明答案性质，例如“答案”“原题参考答案”“原网页参考答案”“手写参考答案（待核验）”“原卷作答”。
3. 来源没有答案时只保留题干，不得自行编造答案。
4. 手写答案、原卷作答保持质疑：疑似错误、矛盾、无法核验处保留并标注，不静默改成正确答案，也不删除原答案。
5. 同一道题多个来源答案冲突时，在同一 Callout 内并列保留，并加 Warning Callout 说明疑点。

标准格式：

```markdown
**1.**（来源：[[某试卷]]、[[另一试卷]]）  
完整题干...

> [!answer]- 原题参考答案
> 答案正文。
>
> 多段答案、公式、表格、列表的每一行都必须保持在引用范围内。
```

## 十一、整理流程

1. 完整阅读 [[通用要求]] 与本文件。
2. 读取课程 `笔记` 目录，确定章节编号与名称。
3. 遍历课程 `真题整理` 目录中的全部 Markdown 文件，逐份完整读取。
4. 逐题提取题干，判断所属章节和题型；不可拆分的多类型题目归入综合题。同一题在不同试卷重复出现时先逐份提取，再对完全一致的题目合并。**暂时无法判断所属章节的题目先收入“其他未归类题目”章节，不得搁置或省略。**
5. 将题目写入对应章节的对应题型下，完整保留题干；英文题按第五条规则译为中文。
6. 标注来源 wikilink；完全一致的重复题合并并列全部来源，表述不一致的分列。
7. 有答案时用 `> [!answer]-` 紧跟收录，并注明答案性质。
8. 处理跨章题、无法归类题、要点式记录、图片缺失、答案矛盾等特殊情况并加必要说明；无法归类题统一收入“其他未归类题目”章节。
9. 对照全部真题文件检查题目零遗漏、题干零删减（含翻译后信息完整）、已有答案零遗漏。
10. 检查 Markdown、YAML、公式、表格、wikilink、Callout 和标题层级，并在 Obsidian 阅读模式验证渲染。

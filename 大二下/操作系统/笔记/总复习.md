## 五、死锁基础
### 3. 四个必要条件
1. **互斥**：某资源一段时间只能被一个进程占有。
2. **请求并保持**：进程已持有至少一个资源，又等待其他进程占有的资源。
3. **不可抢占**：资源只能由占有者完成后主动释放。
4. **循环等待**：存在环 $P_0\to P_1\to\cdots\to P_n\to P_0$，每个进程等待下一个进程占有的资源。
四条件是必要而非充分：四条件可能成立但尚未必已经死锁；破坏任一条件则一定不会死锁。
### 4. 资源分配图
基本事实：

- 图无环，一定无死锁。
- 若每类资源只有一个实例，图有环就发生死锁。
- 若某类有多个实例，图有环只表示可能死锁，还需简化或检测。
### 5. 资源分配图简化与死锁定理
> **死锁定理**：系统状态 $S$ 为死锁状态，当且仅当 $S$ 的资源分配图不可完全简化。不同合法简化顺序最终得到同一个不可简化图。

## 六、死锁处理策略与预防
### 1. 四类策略

| 策略       | 思想                     | 代价/特点                                   |
| -------- | ---------------------- | --------------------------------------- |
| 忽略（鸵鸟算法） | 假装不会发生死锁               | 实现简单；死锁发生后可能只能重启，UNIX/Windows 等会在部分场景采用 |
| 预防       | 静态破坏四个必要条件之一           | 限制强，资源利用率或并发度较低                         |
| 避免       | 动态检查分配后是否仍处于安全状态       | 需进程事先声明最大需求                             |
| 检测与解除    | 允许死锁，定期检测，发生后抢占资源或终止进程 | 需维护请求/分配信息和恢复机制                         |

## 七、安全状态与银行家算法

> 安全状态一定无死锁；不安全状态表示**可能**死锁，不等于已经死锁。死锁避免的目标是永不进入不安全状态。
### 2. 数据结构

设有 $n$ 个进程、$m$ 类资源：

- `Available[m]`：每类当前可用实例数。
- `Max[n,m]`：各进程声明的最大需求。
- `Allocation[n,m]`：当前已分配量。
- `Need[n,m] = Max - Allocation`：尚需资源量。
### 3. 安全性算法

```text
Work := Available
对所有 i：Finish[i] := false
重复寻找 i，使 Finish[i] = false 且 Need[i] <= Work：
    Work := Work + Allocation[i]
    Finish[i] := true
直到找不到这样的 i
若所有 Finish[i] 都为 true，则安全；否则不安全
```

### 4. 资源请求算法

收到 $P_i$ 的请求向量 $Request_i$：

1. 若 $Request_i>Need_i$，说明超出声明的最大需求，报错。
2. 若 $Request_i>Available$，资源暂不可用，$P_i$ 等待。
3. 否则试分配：

$$
Available:=Available-Request_i
$$

$$
Allocation_i:=Allocation_i+Request_i,\qquad Need_i:=Need_i-Request_i
$$

4. 执行安全性算法。安全则正式分配；不安全则回滚状态并让 $P_i$ 等待。

### 2. 预防方法

1. **互斥**：许多资源天然必须互斥，通常不能破坏，反而应保证。
2. **破坏请求并保持**：要求进程执行前一次申请全部资源，或仅在未占有任何资源时才能申请。缺点是资源利用率低且可能饥饿。
3. **破坏不可抢占**：新申请不能满足时，进程释放已占有资源；已释放资源进入其等待列表，待旧资源和新资源均可获得时重新开始。
4. **破坏循环等待**：对资源类型线性编号，只允许按递增序申请。难点是合理编号，会限制新设备加入、实际使用顺序和用户编程自由。

预防严格地让至少一个必要条件不成立；避免则允许必要条件存在，但在每次分配时阻止系统进入不安全状态，以换取更高利用率。
## 八、死锁检测与解除
### 1. 检测算法
```text
Work := Available
若 Allocation[i] != 0，则 Finish[i] := false；否则 Finish[i] := true
重复寻找 i，使 Finish[i] = false 且 Request[i] <= Work：
    Work := Work + Allocation[i]
    Finish[i] := true
直到找不到这样的 i
若仍有 Finish[i] = false，则系统死锁，且这些 Pi 是死锁进程
```
### 3. 解除死锁

1. **抢占资源**：从一个或多个进程抢占足够资源交给死锁进程。需要选择牺牲者、回滚到安全状态，并防止同一进程反复成为牺牲者而饥饿。
2. **终止进程**：可一次终止所有死锁进程，或逐个终止直到环消失。逐个终止时应综合优先级、已运行与剩余时间、已占及尚需资源、进程是交互式还是批处理式，尽量降低代价。

# 4.1 进程同步
## 一、进程同步的基本概念

### 1. 任务与两类制约关系

| 制约关系     | 含义                           | 典型来源                     |
| -------- | ---------------------------- | ------------------------ |
| 间接制约（互斥） | 多个进程竞争同一临界资源，同一时刻只允许一个使用     | 共享变量、打印机、缓冲区指针           |
| 直接制约（同步） | 合作进程之间有明确的先后关系，一个事件须等待另一事件发生 | “先生产、后消费”“C1 完成后才能执行 C2” |

- **同步**：两个或多个事件具有某种时序关系（先—后）。
- **互斥**：资源必须排他使用，进程之间没有固定先后，只要求不能同时进入。互斥可视作一种特殊同步。
- **临界资源**：一次只允许一个进程使用的资源，也称互斥资源；共享变量也可能成为临界资源。
### 4. 临界区及一般结构
同步机制应满足：

1. **空闲让进**：临界区空闲时，应允许某个申请者立即进入；
2. **忙则等待**：已有进程在临界区时，其他申请者必须等待；
3. **有限等待**：申请进入后，等待时间应有上界，不能“死等”或饥饿；
4. **让权等待（可选准则）**：暂不能进入者应释放 CPU、转入阻塞，而不是持续忙等。

## 五、分页存储管理

### 第一类：地址结构与地址转换（第5章）

#### 公式 1️⃣ 逻辑地址的位结构

$$\text{逻辑地址}=(p,d),\qquad \text{页号 }p\text{ 占 }m-n\text{ 位},\quad \text{页内地址 }d\text{ 占 }n\text{ 位}$$
#### 公式 2️⃣ 由地址求页号与页内地址

$$p=\lfloor A/L\rfloor,\qquad d=A\bmod L$$
#### 公式 3️⃣ 物理地址计算（核心）

$$\text{物理地址}=f\times L+d$$

- **符号**：$f$=物理块号（查页表得到），$L$=块大小，$d$=页内偏移。
- **意义**：页 $p$ 实际放在物理块 $f$，块 $f$ 的起始地址是 $fL$，加偏移 $d$ 即真实地址。**用的是 $f$ 不是 $p$**——这正是页表的作用。 [cite:2077e6d4-6]

#### 公式 5️⃣ TLB 有效访问时间 EAT（第5章版）

$$\text{一次逻辑访问}=2\text{ 次主存访问（查页表 + 取数据）}$$

$$EAT=\alpha(\lambda+t)+(1-\alpha)(\lambda+2t)=\lambda+(2-\alpha)t$$

- **符号**：$\lambda$=TLB 查询时间，$t$=一次内存访问，$\alpha$=TLB 命中率。
- **意义**：加 TLB 后一次访存的平均耗时。命中（概率 $\alpha$）只花"查TLB+访存"；未命中（概率 $1-\alpha$）要"查TLB+查内存页表+访存"。 [cite:d1c7182a-14]
- **真题**（2016-2017 A卷）：TLB 100ns、页表 180ns、目标 EAT=150ns → 代入反解 $\alpha≈72\%$。 [cite:d1c7182a-1]
- **配套知识**：TLB 容量约 16～512 项，靠局部性命中率可达约 90%。 [cite:d1c7182a-14]

### 第二类：缺页与性能（第6章）

#### 公式 6️⃣ 缺页率

$$f=\frac{F}{A}=\frac{F}{S+F}$$

- **符号**：$S$=成功访问次数，$F$=缺页次数，$A$=总次数。
- **意义**：缺页频繁程度的度量。影响因素：页大小、分配页框数、置换算法、程序局部性。 [cite:c0882b5b-1]
- **真题例**：引用串 `432143543215`（12次），FIFO(M=3) 缺页 9 → $9/12=75\%$。 [cite:c0882b5b-4]

#### 公式 7️⃣ 缺页服务时间（考虑脏页写回）

$$t_{pf}=\beta\,t_{dirty}+(1-\beta)\,t_{clean}$$

- **符号**：$\beta$=牺牲页被修改过的概率，$t_{dirty}$=处理脏页缺页时间（含写回），$t_{clean}$=处理干净页缺页时间。
- **意义**：被换出的页若修改过（脏位 M=1）必须先写回磁盘，花更多时间；平均缺页时间按修改概率加权。 [cite:c0882b5b-1]

#### 公式 8️⃣ 请求分页系统 EAT（含缺页）

$$EAT=(1-p)\cdot200+p\cdot8{,}000{,}000\ \text{ns}=200+7{,}999{,}800p\ \text{ns}$$

- **符号**：$p$=缺页概率，200ns=普通访存，8ms=平均缺页处理。
- **意义**：缺页概率为 $p$ 时一次访存的平均时间。若 $p=0.001$，$EAT≈8.2\mu s$，**慢约 40 倍**——缺页即使很少也极昂贵。 [cite:c0882b5b-1]

#### 公式 9️⃣ EAT 三种路径（更精细版）

$$\text{TLB命中}:\lambda+t;\quad \text{页在内存但TLB未中}:2(\lambda+t);\quad \text{页不在内存}:\varepsilon+2(\lambda+t)$$

- **符号**：$\varepsilon$=缺页处理时间。
- **意义**：三种情形分别对应三种开销，实际 EAT 再按各自概率加权。是公式5、8的统一概括。 [cite:d1c7182a-13]

### 第三类：内存分配与工作集（第6章）

#### 公式 1️⃣0️⃣ 按比例分配物理块

$$b_i=\frac{S_i}{S}\,m$$

- **符号**：$S_i$=进程 i 页数，$S=\sum S_i$，$m$=可用物理块总数。
- **意义**：按进程大小成比例分块，避免大进程小进程分得一样多；结果取整且**不低于最小物理块数**（足以执行一条最复杂指令）。 [cite:c0882b5b-11]

#### 公式 1️⃣1️⃣ 工作集及其性质

$$W(t,\Delta)=\{\text{最近 }\Delta\text{ 次/时间内访问的页}\},\qquad W(t,\Delta)\subseteq W(t,\Delta+1)$$

- **符号**：$t$=时刻，$\Delta$=窗口长度。
- **意义**：工作集 = 窗口内访问过的不同页集合，用它估计进程当前局部性需要的页框数。窗口越大集合只增不减。 [cite:c0882b5b-6]

#### 公式 1️⃣2️⃣ L=S 准则（预防抖动）

$$L=S$$

- **符号**：$L$=两次缺页平均间隔，$S$=一次缺页平均服务时间。
- **意义**：$L>S$ 缺页少、磁盘有余力；$L<S$ 分页设备跟不上、应暂停部分进程；$L≈S$ 时磁盘与 CPU 协调利用。Denning 1980 年提出。 [cite:c0882b5b-2][cite:c0882b5b-13]

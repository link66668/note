### 三、名词解释与简答（本大题共 3 小题，每小题 2 分，共 6 分）

**1.** DML。

> [!answer]- 原卷参考答案
> 数据操纵语言（Data Manipulation Language），由 DBMS 提供，用于让用户或程序员使用，实现对数据库中数据的操作。

**2.** 事务。

> [!answer]- 原卷参考答案
> 数据库系统的一个操作序列，这些操作或者都做，或者都不做，是一个不可分割的工作单位。

> [!answer]- 原卷参考答案

| Employee: Emp_no | Emp_name | Dept_no |

| 1009             | 林冲       | D1      |

用 SQL 语言实现：查询除了“Apollo”项目之外，其余各项目的预算经费的平均值。（3 分）
(2) 写出“查询未参加任何项目的人员的员工号”的关系代数表达式和 SQL 查询语句。
(3) 分别用 IN 谓词和子查询（无多表连接）、多表连接的 SQL 语言来实现：查询“花荣”所参加的项目的项目号和他所担任的工作，并按项目号降序排列输出。
(4) 用 SQL 语言实现：向基本表 Project 中插入一个新项目，项目名为“Mars”，项目编号为“P4”，预算经费未知；从基本表 Works 中删除工作性质未知的元组；将预算经费超过 15 万元的所有项目的预算缩减 5%。（9 分）
(5) 将基本表 Works 中参加“P2”项目的“职员”的员工号定义为一个视图 V_Clerk(Emp_no)。（3 分）
(6) 将下列 SQL DDL 语句补充完整（3 分）：
CREATE TABLE Works（Emp_no INTEGER，Pro_no CHAR(4)，Job CHAR(20)，PRIMARY KEY (　)，FOREIGN KEY (　) REFERENCES Employee (　)，FOREIGN KEY (　) REFERENCES Project (　)）

> [!answer]- 原卷参考答案
> (1) SELECT Pro_no, COUNT(DISTINCT Job) FROM Works GROUP BY Pro_no；SELECT AVG(Budget) FROM Project WHERE Pro_name <> 'Apollo'
> (2) 关系代数：$\pi_{Emp\_no}(Employee) - \pi_{Emp\_no}(Works)$；SQL（必须采用 NOT EXISTS 和相关子查询）：SELECT Emp_no FROM Employee WHERE NOT EXISTS (SELECT * FROM Works WHERE Employee.Emp_no = Works.Emp_no)
> (3) 使用 IN 谓词和子查询（无多表连接）：SELECT Pro_no, Job FROM Works WHERE Emp_no IN (SELECT Emp_no FROM Employee WHERE Emp_name = '花荣') ORDER BY Pro_no DESC；多表连接：SELECT Pro_no, Job FROM Works, Employee WHERE Works.Emp_no = Employee.Emp_no AND Emp_name = '花荣' ORDER BY Pro_no DESC
> (4) INSERT INTO Project (Pro_no, Pro_name) VALUES ('P4', 'Mars')（或 INSERT INTO Project VALUES ('P4', 'Mars', NULL)）；DELETE FROM Works WHERE Job IS NULL；UPDATE Project SET Budget = Budget * 0.95 WHERE Budget > 150000
> (5) CREATE VIEW V_Clerk(Emp_no) AS SELECT Emp_no FROM Works WHERE Pro_no = 'P2' AND Job = '职员'
> (6) PRIMARY KEY (Emp_no, Pro_no)；FOREIGN KEY (Emp_no) REFERENCES Employee (Emp_no)；FOREIGN KEY (Pro_no) REFERENCES Project (Pro_no)

**2.** 小区每套房屋可能有多名业主，一名业主也可能在小区内有多套房屋。业主信息包括业主姓名（可能会重名）、身份证号、房号、房屋面积，其中房号不重复。根据需求分析，设计关系模式：
业主（业主姓名，业主身份证号，房号，房屋面积）
(1) 给出“业主”关系的候选键。（3 分）
(2) 它是否满足 2NF 以上的范式，请描述理由。（3 分）
(3) 将其分解为 BCNF 范式，分解后的关系名依次为 A1、A2、A3，并用下划线标示分解后的各关系模式的主键。（4 分）

> [!answer]- 原卷参考答案
> (1) 候选键：（业主身份证号，房号）。
> (2) 不满足 2NF。候选键（业主身份证号，房号），业主姓名对候选键存在部分函数依赖（业主身份证号→业主姓名），房屋面积也存在部分函数依赖（房号→房屋面积）。
> (3) A1（$\underline{\text{业主身份证号}}$，业主姓名）；A2（$\underline{\text{房号}}$，房屋面积）；A3（$\underline{\text{业主身份证号，房号}}$）。

**3.** 考虑关系模式 R(A,B,C,D)，写出满足以下函数依赖时 R 的码，并给出 R 属于哪种范式（1NF、2NF、3NF 或 BCNF）。
已知有：B→C，B→D，CD→A

> [!answer]- 原卷参考答案
> (1) 候选码：B。因为 B→C，B→D，CD→A，即 B 能确定 A、C、D，所以 B 为候选码。
> (2) B 为主属性，A、C、D 为非主属性，均完全函数依赖于码 B，属于 2NF；但非主属性 A 通过 CD→A 传递依赖于码 B（B→CD，CD→A），所以不是 3NF。
